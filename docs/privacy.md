# Privacy and data handling

PaperDesk stores PDF originals, folders, extracted text, translations, annotations, conversations and preferences on the user's computer. Its local web server listens on loopback only. macOS API keys use the login Keychain. Display-name changes do not change the persistent storage directory or Keychain service.

When a paper is imported or opened with automatic translation enabled (the default), an AI provider configured and translation visible, PaperDesk automatically queues all missing translatable body text, headings and captions using that provider. References, display equations and page furniture are excluded. Results appear as each paragraph completes. Saved translations are reused. Turn off “Automatically translate body when opening a paper” in Settings to start translations manually instead. Hiding translations also disables this automatic start; interrupted, failed or cancelled jobs require an explicit action to continue. While a job runs, paragraphs missing from a reply are re-requested one at a time (up to two more times) and a dropped connection, timeout or server error is re-sent after a short pause; each retry is another request to the provider and can use quota. Sign-in, usage-limit and model errors stop the job without retrying.

When a user invokes a cloud AI task, the selected passage or requested paper text, relevant surrounding context, title, question and selected figure/region image can be transmitted to the selected provider. A paper summary can send a larger portion of the paper than a passage translation. Codex/Claude CLI tasks use the official CLI's authenticated connection; the app does not collect or export those credentials. Provider usage, retention and account terms apply. PaperDesk does not claim that cloud AI runs offline.

When a PDF is imported, and once for papers added before this feature, PaperDesk looks up the paper's details (authors, year, venue, DOI, arXiv number and research field) on arXiv and OpenAlex. The requests contain the paper's title and any arXiv number or DOI printed on its first page; no PDF or other text is sent. Turn off “Look up paper details automatically” in Settings to stop this; copying BibTeX or choosing “Look up paper details again” still looks a paper up on request. When a paper is imported without choosing a folder and an AI provider is configured, PaperDesk asks that provider to choose one of the user's folders or name a new one (“Organize papers added without a folder”, on by default). That request contains the title, the details found, up to 3,000 characters of the first page's text and the names of the user's folders. The Unfiled view's Auto-organize button sends the same for each paper there, after a confirmation.

Ollama or an OpenAI-compatible service sends input to the configured address. It stays on this Mac only if the address and inference runtime are local. arXiv/OpenAlex lookup and download actions contact those services. External links open their destination. Update checks contact the configured update host when enabled or manually requested. Source installs (scripts/install_source.py) ask once whether to update automatically; when enabled, the app runs `git fetch` against the repository's origin (GitHub) in the background with the user's own git and credentials (git is told never to prompt), and applies fetched commits the next time it opens. Only the repository is contacted; no library content, identifiers or usage data are sent. On first entry, if no provider has been chosen, PaperDesk checks existing Codex/Claude CLI logins without sending an inference request and selects an available CLI and supported model (the latest available Luna for Codex). A saved provider is not automatically replaced by a different provider. Apart from the automatic translation, details lookup and organizing described above, nothing is uploaded at import, and there is no built-in telemetry upload.

Source documents are untrusted input, not instructions. HTML output is sanitized. Codex translation requests ignore user-configured hooks/MCP setup and disable shell/unified execution, shell snapshots and multi-agent features while retaining a read-only sandbox. Claude Code is invoked without tools. These are scoped controls, not a claim that the PDF renderer or an external CLI is invulnerable. Keep bundled components and official CLIs updated.

Local backups include private content and are unencrypted. They exclude keys, browser storage and CLI login files. Previous full libraries retained during restore remain private local data and are not automatically removed. Removing the app bundle does not remove the library. The diagnostics export has an explicit metadata allowlist and does not include user content, credentials or logs. Diagnostic files are not automatically sent anywhere.

Document structure analysis uses Docling locally in a separate CPU process. The initial model download contacts Hugging Face for the pinned public Heron model; it does not send the PDF. The model cache, analysis results and local worker logs remain in the application data directory. Once the required model files are cached, analysis runs in offline mode. OCR and remote document analysis services are disabled. Analysis caches and model downloads are omitted from content backups and can be regenerated.
